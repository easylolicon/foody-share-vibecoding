# 今天吃什么：外卖记录信息流设计

## 目标与范围

这是一个让用户发布“今天吃了什么”的公开记录网站。用户无需注册，填写昵称即可提交 1-3 张外卖图片和一句话描述；其他用户通过首页浏览这些记录、查看多图详情并点赞。首版不做独立分享链接、关注、评论、推荐算法或复杂筛选。

## 技术架构

- Node.js + Express 提供页面和 REST API。
- EJS 服务端渲染页面，原生 JavaScript 负责弹窗、预览、异步提交和点赞。
- `mysql2` 连接 MySQL；数据库连接通过环境变量配置。
- `multer` 接收图片并写入本地 `uploads/` 目录。
- `StorageProvider` 定义保存、生成访问 URL、删除文件的接口；首版实现 `LocalStorageProvider`，未来可替换为腾讯 COS 或火山 TOS 实现。
- `dotenv` 管理数据库、上传目录和对象存储配置。
- Express 静态资源路由暴露本地上传文件。

## 页面与交互

### 首页

- 顶部显示产品名和轻量刷新区域。
- 内容区按本地日期分组，每个日期显示一条横向滚动轨道；PC 端根据宽度展示多张卡片，手机端保持横向滑动。
- 卡片图片使用稳定比例容器；卡片显示图片、昵称、描述、时间和点赞按钮。
- 多图记录在卡片内轮播，提供前后箭头和页码圆点；点击当前图片仍可打开详情弹层查看完整图片组。
- 右下角固定悬浮“发布今天吃的”按钮。
- 支持分页加载更多、加载中、空状态和失败重试。

### 发布弹窗

- 点击悬浮按钮打开桌面端居中、移动端接近全屏的弹窗。
- 选择 1-3 张图片，支持缩略图预览、删除和排序。
- 昵称必填，描述选填，字段长度由服务端再次校验。
- 提交期间锁定按钮并显示状态；失败时保留文本和可重试状态。
- 成功后关闭弹窗、刷新首页，新记录插入列表顶部。

## 数据模型

### `posts`

- `id`、`nickname`、`description`、`like_count`、`created_at`、`updated_at`

### `post_images`

- `id`、`post_id`、`url`、`sort_order`、`created_at`
- `post_id` 外键关联 `posts.id`，删除记录时级联删除图片元数据。

### `post_likes`

- `id`、`post_id`、`visitor_id`、`created_at`
- 对 `post_id + visitor_id` 建立唯一约束，防止同一浏览器重复点赞。

浏览器首次访问时生成随机 visitor ID 并保存在 localStorage；点赞请求携带该 ID。该机制只用于首版匿名去重，不承担身份认证。

## API

- `GET /api/posts?page=1&pageSize=24`：按 `created_at DESC` 返回分页记录及图片列表。
- `POST /api/posts`：使用 `multipart/form-data` 创建记录，字段为昵称、描述和 1-3 张图片。
- `GET /api/posts/:id`：返回单条记录及全部图片。
- `POST /api/posts/:id/like`：切换当前 visitor 的点赞状态，返回 `liked` 和最新 `likeCount`。
- `GET /uploads/:filename`：提供本地图片访问。

## 发布数据流与失败处理

1. 前端选择图片并在弹窗中预览。
2. 后端校验昵称、描述、文件数量、MIME 类型和单文件大小。
3. `StorageProvider` 保存文件并返回 URL。
4. 在 MySQL 事务中写入 `posts` 与 `post_images`。
5. 任一步骤失败时回滚事务并删除已经写入的文件。
6. 成功后返回完整记录，前端插入首页顶部。

文件名使用随机 ID，上传目录自动创建；拒绝路径穿越和未知文件类型。数据库错误、上传失败和无效请求返回统一 JSON 错误结构。

## 迁移

迁移文件位于 `database/migrations/`：

- `001_create_posts.sql`
- `002_create_post_images.sql`
- `003_create_post_likes.sql`

`run-migrations.js` 按文件名顺序执行，并在迁移记录表中记录已执行文件，支持在空数据库初始化和重复运行。

## 测试与验收

- 空 MySQL 数据库可通过迁移脚本初始化。
- 字段、图片数量和文件类型/大小校验覆盖成功与失败路径。
- 本地存储适配器覆盖保存、URL 生成和删除。
- 创建记录失败时数据库和文件均回滚。
- 分页按最新时间排序。
- 重复点赞不会重复计数，取消点赞可恢复状态。
- Playwright 端到端流程覆盖：打开首页、发布 3 张图、首页出现新记录、点赞数量更新。

## 后续扩展边界

切换 COS/TOS 只新增存储适配器和配置，不改变数据库模型、API 或页面。若未来增加账号、评论或内容审核，应作为独立设计和迁移任务处理。
